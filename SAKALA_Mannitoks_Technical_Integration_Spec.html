Part 1
System Overview
Architecture, integration layers, and money flow

The SAKALA x Mannitoks integration connects three distinct layers: the diaspora payment layer (where subscribers and remittance senders live), the treasury and trust layer (where funds are split and held accountable), and the Haiti operations layer (where money becomes youth jobs, franchise inventory, and community wealth).

Mannitoks sits at the center. It is the single payment backbone that touches all three layers.

Key Design Principle

Every dollar is split before it touches a human decision-maker. The smart contract enforces percentages. The Mannitoks API handles the Haiti-side disbursement. No one can redirect funds because no one has custody between split and deposit.

Part 3 — Integration Point 2
Remittance Pipeline
$1/transaction Community Wealth Fund contribution

This is the engine. Every remittance transfer through Mannitoks routes $1.00 to the SAKALA Community Wealth Fund. The sender pays less than Western Union. The family receives more. And $1 creates a youth job. Not a donation... a better product.

Fee Architecture (Per $200 Transfer)

Component Amount Recipient Purpose
Platform operations $3.50 Mannitoks Processing, compliance, bank fees
Partner margin $0.50 Mannitoks Revenue margin
Community Wealth Fund $1.00 SAKALA Fund Youth franchise deployment
Total fee $5.00
Competitive Position

Western Union charges $8-12 for the same $200 transfer. At $5.00 total, the sender saves $3-7 per transaction and funds a youth job in Haiti. This is not charity... it is a price advantage with social return built in.

API Integration Requirements

The $1 routing must be programmatic and automatic. No manual intervention per transaction.

Default Opt-In (Behavioral Economics)

The $1 contribution is default ON with opt-out available. This is not a dark pattern... it is proven behavioral science. Research consistently shows 70-85% retention when a prosocial contribution is the default versus 5-15% when it requires opt-in. The sender sees the contribution clearly on the fee breakdown. They can remove it with one tap. Most do not.

Transparency Dashboard

Every contributing sender gets a real-time view of where their dollars go:

  • Total Community Wealth Fund balance
  • Number of franchises funded this quarter
  • Number of youth employed
  • Site-by-site deployment map
  • Quarterly impact statements pushed to sender inbox

Integration Channels

1. Direct Consumer Sales (MACHE Storefront)

Each SAKALA franchise listed as a MACHE seller. Individual consumers in Haiti purchase via the app. Payment settles through Mannitoks wallet infrastructure.

2. Bulk Institutional Sales

Restaurants, hotels, diaspora grocery stores, and cooperatives order in bulk via MACHE. This channel handles B2B transactions with volume pricing and recurring orders.

3. Harvest Box Subscription Fulfillment

MACHE tracks inventory and fulfillment for TapTap Harvest Box subscribers. When a diaspora subscriber's $90 quarterly payment arrives, the system triggers product sourcing from franchise sites and tracks shipment status through to delivery.

  • Order management: MACHE order → franchise site notification → fulfillment confirmation
  • Revenue attribution: Sales revenue tracked per franchise, per youth team, per product line
  • Quality certification: Each product listing includes franchise certification status

Processing Architecture

The question is where the US-side payment processing lives. Two models:

Model A: Mannitoks End-to-End

If Mannitoks can process US-based recurring card payments (Visa/MC), the entire flow stays on one platform. Subscriber card → Mannitoks → programmatic split → Haiti wallets. Simplest integration. One vendor. One reconciliation.

Model B: Stripe (US) + Mannitoks (Haiti)

If Mannitoks cannot process US-based recurring payments, we use Stripe or Square for the US card charge, convert to USDC, and route to Mannitoks via API for Haiti-side disbursement. More moving parts but keeps Mannitoks as the Haiti payment backbone.

Recurring Billing Requirements

  • Frequency: Quarterly (every 90 days)
  • Auto-charge: Subscriber authorizes recurring debit at enrollment
  • Retry logic: Failed charge → retry at 3 days, 7 days, then pause + notification
  • Cancellation: Subscriber can cancel anytime, effective next quarter
  • Upgrade path: $90 (standard), $150 (double impact), $300 (patron tier)

Part 6 — Integration Point 5
Youth Payroll
310 youth today, 3,440 at full scale across 344 franchises

This is where the integration touches individual lives. Every franchise worker receives pay through the Mannitoks system... deposited to their wallet, accessible via NFC card, cashable at any MonCash or NatCash agent point.

Payroll Flow

1
Hours Logged
Youth logs hours via franchise manager. Simple time tracking (mobile form or USSD-based for low-connectivity sites).
2
Manager Approval
Franchise manager reviews and approves hours for the pay period. Disputes flagged to SAKALA regional coordinator.
3
Payroll Calculation
System calculates pay: base rate + output bonus (kg harvested, items processed). Calculated in HTG.
4
Bulk Disbursement
SAKALA ops wallet triggers bulk payout via Mannitoks API. All approved payroll for the period executes in a single batch call.
5
Youth Receives Funds
Deposit hits Mannitoks wallet instantly. SMS notification sent. Youth can tap NFC card at merchant or cash out at MonCash/NatCash agent.

Cash-Out Options for Youth

  • NFC card tap at merchant POS: Direct payment for goods and services. No cash handling.
  • MonCash agent cash-out: Transfer from Mannitoks wallet to MonCash, withdraw at any of MonCash's 10,000+ agent points.
  • NatCash agent cash-out: Same flow via NatCash (Natcom network).
  • ATM withdrawal: Via NFC card at compatible ATMs (Unibank, Sogebank networks).
  • Peer transfer: Wallet-to-wallet between SAKALA youth (e.g., shared transportation costs).

Part 9
The 5 Questions for Chris
Critical infrastructure decisions that determine partnership architecture

Everything above is our proposal. The answers to these five questions determine what is possible, what needs workarounds, and what the timeline actually looks like.

5 Critical Questions for Mannitoks
  1. Card Issuance: Can Mannitoks issue co-branded prepaid NFC smart cards on your existing card rails? What is the minimum order quantity, per-card cost, and production timeline for a 100-card batch? This determines whether we can put physical cards in youth hands within 6 weeks or need an alternative provider.
  2. Programmatic Splits: Can your API handle automated transaction splitting... routing a fixed $1.00 to a designated wallet on every remittance, and splitting Harvest Box payments into 5 wallets by percentage? This determines whether the payment architecture is one platform (Mannitoks end-to-end) or two (Stripe US + Mannitoks Haiti).
  3. Bulk Disbursement: Does Mannitoks support batch payouts to 300+ wallets in a single API call? What is throughput, latency, and per-transaction cost at that scale? This determines payroll feasibility. If batch is not supported, we need to build a queue system on our side.
  4. MACHE API: Does the MACHE agricultural marketplace have API endpoints for seller onboarding, inventory management, and order tracking? Or is it currently manual? This determines whether SAKALA franchise products integrate programmatically or require manual listing and fulfillment.
  5. US-Side Processing: Can Mannitoks process recurring credit/debit card payments from US-based subscribers? If not, can your API accept inbound USDC or USD wire transfers for Haiti-side distribution? This determines the $90 Harvest Box billing architecture and whether we need Stripe for the US leg.
What We Are Not Asking

We are not asking Mannitoks to build new technology. We are asking what your platform already does, what it can do with minor configuration, and what falls outside your current capability so we can architect around it. Every integration point above has a fallback plan. We just need to know which path to take.
